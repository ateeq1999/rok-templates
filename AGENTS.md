# AGENTS.md — working in rok-templates

`rok-templates` is one member repo of the rok toolchain (see
`rok-workspace`, the folder around it). It holds the starter templates
the rok-data engine's `init --template` writes — `actix-api`,
`axum-api`, `grpc-api` (tonic, sharing axum-api's transport-free files),
and `monorepo` (an axum API with web, mobile and desktop
Apps and generated clients) — embedded by `build.rs`, plus the catalog
code that maps a template name to the files a project gets.

## Where a change belongs

| Change | Touch |
| --- | --- |
| A template's files | `templates/<template>/` (`actix-api`, `axum-api` and `grpc-api` are their own crates, excluded from this workspace) |
| Which files a project gets, renaming at init | `src/catalog.rs`, `src/rename.rs` (and their unit tests) |
| A file both API templates share | both copies; `tests/template_drift.rs` keeps them identical (and `grpc-api`'s copy of the files it shares with `axum-api`) |
| A `.proto` or tonic service of `grpc-api` | generated: its schema and `rok-data-sqlc.toml`, then regenerate; `build.rs` compiles `proto/` with protox, never `protoc` |
| A template's generated files | regenerate, never edit: `ROK_DATA_SQLC_UPDATE_EXPECTED=1` with the gates (below) |
| How `init` writes files (copy when absent, skip `@generated`) | not here: the rok-data engine's `init` |
| A template guide | `docs/guide/` |

## The gates

`tests/gates/` makes each template into a project with a `rok-data`
generator, generates it, and checks it the way a user's project would be
checked: drift against what is checked in, `cargo` checks and tests, the
monorepo's web (bun), mobile and Dart (Flutter) and desktop (GPUI) Apps.

The generator is the rok-data release in `rok-data.pin`, **built against
this checkout**: `init` copies the templates embedded in the binary, so a
stock install would test the published templates instead. The gates
refuse a binary whose templates differ from this checkout.

```console
$ git -C ../rok-data checkout "$(cat rok-data.pin)"
$ (cd ../rok-data && cargo build -p rok-data-cli --config 'patch.crates-io.rok-templates.path="../rok-templates"')
$ ROK_DATA_BIN=../rok-data/target/debug/rok-data ROK_DATA_PATH=../rok-data cargo test --test gates -- --test-threads=1
```

When this checkout's version is newer than the rok-templates the pinned
rok-data asks for (a rok-templates release ahead of rok-data's), Cargo
ignores the patch and builds the published templates; first set rok-data's
`rok-templates = "=<this version>"` (CI does, and restore it afterwards).

Without `ROK_DATA_BIN` each gate prints why it skips and passes. Run them
one at a time, as CI does: the projects they make share one target
directory and package names (`shop-api`), so two at once overwrite each
other's binaries (the monorepo's `openapi` example among them).
`ROK_DATA_PATH` points the generated projects' `rok-data` dependency at
the same checkout, so runtime and generator match.

Moving the pin is how an engine change to generated template code
reaches the templates: bump `rok-data.pin`, regenerate with
`ROK_DATA_SQLC_UPDATE_EXPECTED=1`, and review the diff. A new minor also
moves `ROK_VERSION` in every template workflow to a rok release of that
minor (`tests/ci_rok_version.rs` checks): template CI downloads that
`rok` release instead of building it.

## Rules

1. `cargo fmt --all` and `cargo clippy --all-targets -- -D warnings`
   clean; the lint set in `Cargo.toml` mirrors rok-data's.
2. Line endings are LF (`.gitattributes`): the catalog's tests and the
   gates compare bytes.
3. Generated files are recognized by their `@generated by rok-data-sqlc`
   (or legacy `@generated by rok-sqlc`) header; never hand-edit them.
4. Template dependencies are pinned exactly — no ranges, no `latest`
   (`tests/mobile_pins.rs` checks the mobile App).

## Decisions

The templates' decisions are rok-data's workspace ADRs, kept there:
0022 (this crate), 0023 (Capabilities), 0024 (jobs), 0025 (AWS
deployment), 0027 (the monorepo template and the catalog), 0029
(Integrations), 0030 (gRPC and services), 0031 (the desktop App), and
0032 (this repo's split). They live at
`https://github.com/ateeq1999/rok-data/tree/main/docs/decisions`.

## Releasing

Tag `vX.Y.Z` equal to `Cargo.toml`'s version, with a `## [X.Y.Z]` section
in `CHANGELOG.md`; `.github/workflows/release.yml` publishes the crate.
rok-data's engine depends on it from crates.io, so a template change
users should get is released here first, then picked up by a rok-data
release.
